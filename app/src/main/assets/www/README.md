# تطبيق مانجا بيور — نسخة 2

## الملفات
- `index.html` — الصفحة الرئيسية
- `styles.css` — كل التنسيقات (الوضع الفاتح/الداكن التلقائي من هنا)
- `config.js` — هنا تحط بيانات Supabase لتفعيل المكتبة المشتركة (اختياري)
- `store.js` — طبقة التخزين (محلي أو مشترك تلقائياً)
- `app.js` — منطق التطبيق كامل
- `supabase-schema.sql` — أوامر إنشاء الجداول على Supabase (تُشغَّل مرة وحدة)

## النشر على Netlify
اسحب المجلد كامل (بكل ملفاته) على Netlify مباشرة — نفس طريقتك المعتادة، ما تحتاج أي بناء (build) أو أوامر.

## لتفعيل المكتبة المشتركة بين كل المستخدمين
بدون هذي الخطوة، كل شخص ينزّل التطبيق يشوف نسخته الخاصة بس (محلية على جهازه).
لتصير مكتبة وحدة يشوفها الكل:
1. سوّي مشروع مجاني على https://supabase.com
2. افتح SQL Editor بمشروعك، انسخ محتوى `supabase-schema.sql` كامل والصقه وشغّله (Run)
3. من Settings → API انسخ Project URL و anon public key
4. افتحهم بملف `config.js` وحط القيمتين بمكانهم
5. ارفع المجلد على Netlify

بعدها أي شخص يفتح رابط التطبيق (حتى أول مرة) يشوف نفس الأعمال والفصول والروابط اللي أضفتها.

**ملاحظة مهمة عن الحجم:** صور الفصول تُخزَّن كنص Base64 داخل قاعدة البيانات، وهذا مناسب للبداية، بس إذا صارت المكتبة كبيرة (مئات الفصول)، الأفضل لاحقاً الانتقال لتخزين الصور عبر Supabase Storage بدل الجدول نفسه — خبرني إذا وصلت لهذي المرحلة وأسوّيها لك.

**ملاحظة أمان:** بالإعداد الافتراضي بملف SQL، أي شخص عنده رابط التطبيق يكدر يضيف/يعدّل/يحذف من المكتبة (مو بس يشاهد). مناسب الآن لمرحلة التجربة. لما تريد تفتحه لعدد أكبر من الناس، أضيفلك تسجيل دخول للمشرف بس.

## ليش ما سويت "جلب تلقائي لكل أعمال موقع" بلصق رابط وحد؟
تقنياً المتصفح ما يكدر يقرأ محتوى موقع ثاني تلقائياً إلا إذا ذاك الموقع يسمح بهذا صراحة (قيود CORS)، وأغلب مواقع المانجا ما تسمح. وحتى لو تجاوزنا هذي، بناء أداة تسحب تلقائياً كامل كتالوج موقع ثاني وتعيد نشره عندنا يعتبر نسخ جماعي لمحتوى محمي بدون إذن، وهذا شي ما أقدر أسويه.
البديل اللي حطيته: زر "إضافة عدة أعمال دفعة وحدة" بمجلد الروابط — تلصق قائمة (عنوان + رابط) لعدة أعمال وتُضاف كلها بثانية، بدل ما تسوي كل عمل لحاله.

## نظام التحميل
من تبويب "الفصول" بأي عمل، زر التحميل جنب كل فصل يحفظه على جهازك (حتى بدون إنترنت بعدين)، ويظهر بقسم "تحميلاتي" بالدرج الجانبي.

## جديد بالنسخة 3

### زر "تعديل" لكل عمل
بمجلد روابط، كل عمل صار فيه زر "تعديل" يفتحلك نفس نموذج الإضافة معبّى ببياناته الحالية، تصلح أي غلط (متل رابط انحط بخانة العنوان بالغلط) بدون ما تحذف العمل وتعيده من جديد.

### تحقق تلقائي يمنع تكرار غلطة "الرابط صار عنوان"
إذا كتبت رابط بخانة العنوان، يطلعلك تنبيه احمر فوري ويرفض الحفظ لين تصححه.

### زر "جلب" — معاينة تلقائية لصفحة واحدة (وليس الموقع كامل)
بجنب خانة "رابط الموقع المصدر"، زر "جلب" يحاول يجيب عنوان العمل + صورة الغلاف + الوصف **من نفس الصفحة اللي حطيت رابطها بس** (نفس فكرة معاينة الروابط بواتساب)، وتراجعها وتعدلها قبل الحفظ. **هذا يحتاج نشر المجلد على Netlify** (فيه ملف `netlify/functions/fetch-meta.js` يشتغل تلقائياً بمجرد رفع المجلد — ما يحتاج إعداد إضافي منك).

### ليش ما سويت "أعطيه رابط موقع ويسحب كل مانهواته وفصوله تلقائياً"؟
هذا طلبته بالتفصيل، وودي أوضح بصراحة ليش ما بنيته:
- **تقنياً**: المتصفح ما يكدر يقرأ محتوى موقع ثاني كامل تلقائياً (قيود CORS)، وحتى بسيرفر (متل دالة fetch-meta)، اكتشاف "كل السلاسل" بموقع يحتاج كود خاص لكل موقع لحاله (كل موقع مانجا مبني بشكل مختلف) — مو شي عام يشتغل على أي موقع تحطه.
- **والأهم**: أداة تسحب تلقائياً فصول وصور مانهوا/مانجا كاملة من موقع ثاني وتعيد نشرها بمكتبتك، حتى لو بنية "Job ID" وتتبع تقدم، تبقى بجوهرها نسخ جماعي لمحتوى محمي بدون إذن أصحابه — وهذا شي ما أقدر أساعد فيه مهما كانت الطريقة اللي يتبنى فيها (زر واحد، قائمة انتظار، أو غيرها).

البديل اللي بنيته بدالها: زر "جلب" فوك (معاينة صفحة وحدة تراجعها بنفسك)، + "إضافة عدة أعمال دفعة وحدة" (تلصق قائمة روابط وتُضاف بثانية)، + تعديل سريع لتصليح الأغلاط. هذا يقلل الكتابة اليدوية كثير من دون ما يتحول التطبيق لأداة نسخ جماعي.

## جديد بالنسخة 4 — التوافق مع "تطبيق سحب بيور" (ارتباط فضفاض)

هذا التطبيق و"تطبيق سحب بيور" تطبيقان منفصلان تماماً برمجياً — ما فيه أي كود بأحدهم يستدعي الثاني مباشرة. الرابط الوحيد بينهم:

1. **نفس إعدادات Supabase** بملفي `config.js` بكل تطبيق (نفس SUPABASE_URL و SUPABASE_KEY)
2. **نفس شكل بيانات العمل (work)** اللي يفهمها هذا التطبيق — أي شي يكتبه أي تطبيق ثاني بنفس هذا الشكل بجدول `works` على Supabase، بيطلع تلقائياً هنا بدون أي تعديل بكود هذا التطبيق:

```js
{
  id, title, titleEn, type,        // "مانجا" | "مانهوا" | "مانها"
  status,                           // "مستمر" | "مكتمل" | "متوقف"
  genres: [],                       // مصفوفة نصوص
  desc, sourceUrl,                  // رابط المصدر يظهر بصفحة التفاصيل
  nextReleaseDate,                  // اختياري، تاريخ YYYY-MM-DD
  cover,                            // رابط صورة أو Base64
  source, publisher, from,
  chapters,                         // عدد الفصول
  avgRating,                        // رقم من 10
  createdAt, updatedAt              // Date.now()
}
```

هذا يعني إذا تحديث أي تطبيق منهم أو استبدلته بالكامل، الثاني يستمر يشتغل عادي طالما البيانات اللي توصل لـ Supabase بنفس الشكل فوك — هذا بالضبط معنى "الارتباط الفضفاض" اللي طلبته.
